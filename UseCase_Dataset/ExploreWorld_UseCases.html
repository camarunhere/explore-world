4Main Application Flows
Flow Step-by-Step Description Actors Involved
🔐 User Registration & Login
  1. Guest opens Register page → fills name, email, password → clicks Create Account.
  2. System validates uniqueness → hashes password (bcrypt) → saves user in MongoDB → sends verification email.
  3. User verifies email → navigates to Login → enters credentials → System issues JWT (24h) in HTTP-only cookie.
  4. User is redirected to the home dashboard as Registered Traveller.
 Guest → Registered Traveller · JWT Auth Service
🔍 Discover & View Destinations
  1. Guest or Traveller opens the home page → browses paginated destination cards.
  2. Uses Search bar (keyword) or Filters (Region, Activity, Difficulty, Rating) → System queries MongoDB → results updated in real-time.
  3. User clicks a destination card → System fetches full post: photos, story, map pin, avg rating, reviews → detail page renders.
  4. Authenticated Traveller sees additional options: Rate, Review, Save.
 Guest / Registered Traveller · MongoDB
📝 Submit a Hidden Destination
  1. Authenticated Traveller clicks "Share a Destination" → form opens.
  2. Fills in: name, region, country, activity type, difficulty, story (min 100 chars), best season, tips.
  3. Uploads at least one photo → System calls Cloudinary API → URL stored.
  4. Clicks Submit → System validates → saves post with status Pending → Admin notified.
  5. Post appears publicly after Admin approval.
 Registered Traveller · Cloudinary · Admin
⭐ Rate & Review
  1. Authenticated Traveller on a destination detail page clicks "Write a Review".
  2. Selects 1–5 star rating + writes review text (min 20 chars) → Submit.
  3. System validates → saves review to MongoDB → recalculates destination's average rating.
  4. New review is immediately visible to all users on the destination page.
 Registered Traveller · MongoDB
🛡️ Content Moderation
  1. Admin logs in → navigates to Admin Dashboard → Content Moderation queue.
  2. Reviews pending posts and flagged/reported content (with report counts & reasons).
  3. For each item: Approve (post goes live), Reject (post removed, reason given), or Delete.
  4. Author is notified by email of the decision.
  5. Auto-hide threshold: content with ≥ 5 user reports is hidden pending Admin review.
 Administrator · Registered Traveller (reporter)
📊 Analytics & User Management
  1. Admin accesses Analytics dashboard → views: total users, new registrations, total approved/pending posts, top-rated destinations, most-searched regions.
  2. Can filter by date range and export data as CSV.
  3. In User Management: searches for a user → views their posts, reviews, and reports → can Suspend (temp) or Ban (permanent).
  4. Banned user's JWT tokens are immediately revoked and they cannot log in.
 Administrator · MongoDB
5Include / Extend & Generalization Reference
From Use CaseRelationshipTo Use CaseExplanation
UC-06 Submit Travel Post
«include»		 UC-14 Upload Image Every submission always uploads at least one photo. UC-06 cannot complete without this step.
UC-10 Report Content
«include»		 UC-11 Moderate Content Every report automatically logs a moderation task and notifies the administrator.
UC-04 Search & Filter
«extend»		 UC-03 Browse Destinations Searching and filtering is an optional extension of basic browsing — users can browse without using filters.
UC-07 Rate & Review
«extend»		 UC-05 View Destination Detail Rating is optional. A user can view a destination without rating it, but rating always starts from the detail page.
UC-01 Register
«extend»		 UC-02 Login After successful registration a user automatically extends into the Login flow to begin their session.
Registered Traveller (actor)
Generalization		 Guest User (actor) Registered Traveller is a specialisation of Guest User — inherits all Guest capabilities (browse, search, view) and adds protected features.
